## 🧩 Problem Definition

Temp0.7 동아리가 커지면서 다음 세 가지 운영 문제가 반복되고 있다.

1. **정보 격차** — 분반원들이 AI/개발 트렌드를 각자 찾아봐야 해서 중복 탐색과 시간 낭비가 발생한다.
2. **운영 공백** — 정기 회의·세미나 발표자 조율이 수동으로 이뤄지다 보니 알림 누락, 발표자 미지정, 회의록 작성 기한 미준수 같은 문제가 반복된다.
3. **정보 재사용성 저하** — 과거 회의록·논의 내용을 다시 찾으려면 디스코드 채널을 일일이 스크롤해야 해서, 기록은 쌓이는데 활용은 안 되고 있다.

## 🎯 Objective

Temp0.7 전용 디스코드 봇을 구축해 다음 세 가지를 자동화한다.

- 분반(웹/앱·데이터AI·피지컬AI) 관심사에 맞는 뉴스를 매일 자동으로 큐레이션해 전달한다.
- 정기 회의 알림과 세미나 발표자 지정을 알림 기반 흐름으로 자동화해 운영 공백을 줄인다.
- 회의록·문서를 RAG 기반으로 색인해, 과거 논의 내용을 질문으로 바로 찾을 수 있게 한다.

새 기능이 늘어나도 기존 모듈에 영향을 주지 않도록 Cog 단위 모듈형 아키텍처로 구축하는 것을 전제로 한다.

## 👥 Target Customer

| 구분 | 대상 | 봇과의 관계 |
|---|---|---|
| 일반 사용자 | Temp0.7 부원 (8명) | 매일 뉴스 수신, 회의 알림 수신, `/질문`으로 회의록 검색 |
| 세미나 발표자 | 그 주 지정된 발표자 3명 | 회의 10분 전 개별 멘션 알림 수신 |
| 관리자 | 팀장(회장) | `/발표자설정`으로 주간 발표자 지정 |
| 운영자 | 동아리 개발 담당 | `/회의설정`으로 정기 회의 시간 관리 |

## 🔄 User Flow

> **Flow 1. 매일 뉴스 큐레이션**
> 1. 스케줄러가 매일 09:00에 뉴스 모듈을 트리거한다.
> 2. 등록된 RSS/API 소스에서 신규 글을 수집한다.
> 3. 분반 관심사 기준으로 관련도를 스코어링해 상위 N개를 선별한다.
> 4. 공지 채널에 임베드 형태로 전송한다.

> **Flow 2. 정기 회의 알림**
> 1. 관리자가 `/회의설정`으로 요일·시간을 등록한다.
> 2. 회의 당일 09:00, 공지 채널에 회의 리마인드가 전송된다.
> 3. 회의 10분 전, `@everyone` 알림과 함께 이번 주 발표자 3명이 멘션된다.

> **Flow 3. 세미나 발표자 지정**
> 1. 회의 다음날 09:00, 팀장에게 "발표자를 설정해달라"는 DM이 전송된다.
> 2. 팀장이 `/발표자설정`으로 이번 주 발표자 3명을 지정한다.
> 3. 지정된 발표자는 다음 회의 10분 전 알림에 반영된다.

> **Flow 4. 회의록 RAG 질의응답**
> 1. 봇이 회의록 채널의 과거 메시지·docx 첨부파일을 백필하고, 이후 신규 항목을 실시간으로 인덱싱한다.
> 2. 부원이 `/질문`으로 궁금한 내용을 입력한다.
> 3. 봇이 벡터 DB에서 관련 내용을 검색해 출처(원본 메시지 링크)와 함께 답변한다.

## ⚙️ Functional Requirements

### 뉴스 큐레이션 모듈

**FR-1. 소스 수집** 🔴 P0
- Description: 등록된 RSS/API 소스에서 매일 신규 글을 수집한다.
- Acceptance Criteria:
  - 매일 09:00 이전에 수집이 완료된다
  - 소스 하나가 실패해도 나머지 소스 수집에 영향을 주지 않는다
  - 수집 실패 시 로그에 소스명과 사유가 남는다

**FR-2. 관련도 큐레이션** 🔴 P0
- Description: 수집된 원본 글을 분반 관심사 기준으로 스코어링해 상위 N개를 선별한다.
- Acceptance Criteria:
  - 3개 분반(웹/앱·데이터AI·피지컬AI) 키워드 기준으로 스코어링된다
  - 선별 개수(N)를 설정값으로 조정할 수 있다
  - 논문 소스는 이 모듈에서 제외된다

**FR-3. 채널 전송** 🟡 P1
- Description: 큐레이션된 글 목록을 임베드 형식으로 공지 채널에 전송한다.
- Acceptance Criteria:
  - 글마다 제목·출처·링크가 표시된다
  - 전송 채널은 설정값으로 지정된다

### 정기 회의 관리 모듈

**FR-4. 회의 스케줄 설정** 🔴 P0
- Description: 관리자가 커맨드로 정기 회의 요일·시간을 등록·수정한다.
- Acceptance Criteria:
  - 관리자 권한이 없는 사용자는 실행할 수 없다
  - 저장 시 기존 스케줄이 있으면 덮어쓴다
  - 저장 즉시 알림 트리거가 새 시간 기준으로 재등록된다

**FR-5. 당일 알림** 🟡 P1
- Description: 회의 당일 09:00에 공지 채널로 회의 리마인드를 전송한다.
- Acceptance Criteria:
  - 회의가 없는 날에는 전송되지 않는다
  - 채널 전송 실패 시 로그가 남는다

**FR-6. 10분 전 전체 알림** 🔴 P0
- Description: 회의 시작 10분 전 공지 채널에 `@everyone` 알림을 전송한다.
- Acceptance Criteria:
  - 회의 시간 변경 시 알림 시각도 함께 갱신된다
  - 알림 문구에 회의 시작까지 남은 시간이 포함된다

**FR-7. 발표자 멘션** 🔴 P0
- Description: 회의 10분 전, 이번 주로 등록된 발표자 3명을 멘션해 알린다.
- Acceptance Criteria:
  - 발표자가 미지정된 주에는 "발표자 미설정" 문구로 대체된다
  - 발표자 3명 모두 개별 멘션(`@유저`)으로 표시된다

### 세미나 발표자 관리 모듈

**FR-8. 발표자 설정 커맨드** 🔴 P0
- Description: 팀장이 커맨드로 이번 주 세미나 발표자 3명을 지정한다.
- Acceptance Criteria:
  - 팀장 계정 외에는 실행이 거부된다
  - 같은 주에 재실행하면 기존 지정 내용이 덮어써진다
  - 지정 완료 시 확인 메시지가 표시된다

**FR-9. 발표자 리마인드 DM** 🟡 P1
- Description: 회의 다음날 09:00, 팀장에게 발표자 설정을 요청하는 개인 메시지를 보낸다.
- Acceptance Criteria:
  - DM 수신이 차단된 경우 실패가 로그로 남는다
  - 회의가 없었던 날의 다음날에는 전송되지 않는다

### 회의록 RAG 질의응답 모듈

**FR-10. 이력·첨부파일 수집** 🟡 P1
- Description: 지정 채널의 과거 메시지와 docx 첨부파일을 텍스트로 추출한다.
- Acceptance Criteria:
  - 최초 실행 시 채널 전체 이력을 1회 백필한다
  - 이후에는 마지막 인덱싱 시점 이후 항목만 처리한다
  - docx의 문단·표 내용이 텍스트로 추출된다

**FR-11. 인덱싱** 🟡 P1
- Description: 추출된 텍스트를 청킹·임베딩해 벡터 DB에 저장한다.
- Acceptance Criteria:
  - 각 청크에 채널명·작성자·작성일·원본 링크가 메타데이터로 저장된다
  - 동일 메시지/첨부파일이 중복 인덱싱되지 않는다

**FR-12. 질의응답** 🟡 P1
- Description: 사용자가 입력한 질문에 대해 벡터 검색 결과를 근거로 답변한다.
- Acceptance Criteria:
  - 답변에 출처(원본 메시지 링크)가 함께 표시된다
  - 관련 내용이 없을 경우 "찾을 수 없음"을 명시한다
  - 응답까지 걸리는 시간이 10초를 넘지 않는다
